### 📰 Selected work.

*Six builds, each told as a magazine spread with its own case-study page.*

#### 01 — SkillVision AI
**Intelligent Career & Skill Intelligence System** — `SKILLS · KNOWLEDGE · CAREER · LEARNING` — *Fig. 01 — Career intelligence*

- **Problem:** Job seekers can't see how their skills map to real roles, and generic career advice ignores what's actually on their resume.
- **Solution:** Parses resumes into structured profiles, scores ATS compatibility, maps skill gaps against target roles, and generates milestone roadmaps, mock interviews, and matched job leads — with RAG retrieval grounding its guidance.
- **Technology:** React · TypeScript · Vite · Tailwind CSS · Express · Google Gemini API
- **My contribution:** Designed and built the platform — resume parsing and ATS scoring flows, skill radar and gap logic, roadmap and interview modules, job-matching engine, and RAG-grounded career guidance.

[Case study](https://somesh-m.vercel.app/projects/skillvision-ai) · [GitHub](https://github.com/Somesh4206/SkillVision) · [Live Demo](https://skillvisionai.onrender.com) — *Story · 01 / 06*

#### 02 — OpenBlueprint
**From Measurements to Intelligent Blueprints.** — `LIVING · KITCHEN · BED · STUDY · 12.4 M — PLOT WIDTH`

`Measure → Analyze → Plan → Visualize → Estimate`

- **Problem:** Early-stage home planning is guesswork: room needs, plot constraints, light, ventilation, and cost are reasoned about separately, if at all.
- **Solution:** Turns natural-language requirements into structured constraints, generates five design strategies with a zone-based BSP layout engine, and offers a CAD-like 2D editor, clay-render 3D views, INR cost estimation, and a RAG knowledge assistant.
- **Technology:** Next.js · TypeScript · Tailwind CSS · Prisma · AI APIs · 3D Visualization
- **My contribution:** Designed and built the platform — strategy generation, BSP-based layout logic, 2D editor tooling, 3D visualization, cost estimation, and the AI/RAG assistants.
- *Note — Preliminary layouts for exploration — not a substitute for a licensed architect.*

[Case study](https://somesh-m.vercel.app/projects/openblueprint) · [GitHub](https://github.com/Somesh4206/OpenBlueprint) — *Spread · 02 / 06*

#### 03 — DiagnoraX
**Your Personal AI Health Companion** — *Fig. 03 — Care flow, conceptual*

`01 SYMPTOMS → 02 AI ANALYSIS → 03 GUIDANCE → 04 DOCTOR → 05 FOLLOW-UP`

- **Problem:** Health information is scattered across prescriptions, lab reports, and memory — hard to organize, easy to misunderstand.
- **Solution:** Centralizes the everyday health workflow: AI symptom checker with severity and next-step guidance, body-composition analysis, doctor recommendations, prescription OCR, interaction warnings, reminders, and report analysis — with Firebase auth and data throughout.
- **Technology:** Flutter · Dart · React · Firebase · Firestore · Google Gemini API
- **My contribution:** Built end-to-end during ML internship — the React web app and its Flutter conversion, Firebase auth and Firestore data, and Gemini-powered assistance flows.
- *Note — A software project for organizing health information — not professional medical diagnosis.*

[Case study](https://somesh-m.vercel.app/projects/diagnorax) · [GitHub](https://github.com/Somesh4206/DiagnoraX-App) — *Story · 03 / 06*

#### 04 — JeduAI Connect
**Smart Learning and Language Empowerment** — `EN · TA · HI + every classroom in between`

`Languages ↔ Students ↔ Teachers ↔ AI`

- **Problem:** Language barriers and manual classroom admin slow down learning in multilingual classrooms.
- **Solution:** Pairs live classes with AI assistance — attendance automation, translation, and multilingual learning paths — coordinated across student, teacher, and admin roles.
- **Technology:** Flutter · Dart · AI APIs · Firebase
- **My contribution:** Designed the multi-role experience and built the Flutter client with Firebase-backed classes, attendance, and translation flows.

[Case study](https://somesh-m.vercel.app/projects/jeduai-connect) · [GitHub](https://github.com/Somesh4206/JeduAI) · [Live Demo](https://jeduai-connect.netlify.app) · [Android APK](https://drive.usercontent.google.com/download?id=1HthWUYS96OI2fh8-SLpyDQl20pb59Ltc&export=download&authuser=0&confirm=t&uuid=8970889b-7c4c-4eff-8266-c136ddc01e45&at=AMrWOn0yi_Wc8XpUL59xFWtqWWvB%3A1789634457840) — *Spread · 04 / 06*

#### 05 — AppleSupport AI
**AI Customer Support Intelligence**

`CUSTOMER ↓ CONVERSATION ↓ RETRIEVAL ↓ AI RESPONSE ↓ ESCALATION`

- **Problem:** Support teams drown in conversations with no systematic way to know what was asked, what worked, and what needs a human.
- **Solution:** A retrieval pipeline over reconstructed conversations — TF-IDF baseline vs. embeddings, RAG retrieval, classification, and an explicit escalation policy, evaluated by LLMs and validated by humans.
- **Technology:** Python · Jupyter Notebook · RAG · Embeddings · TF-IDF · LLM Evaluation
- **My contribution:** Built the conversation-reconstruction and retrieval pipeline, classification and escalation logic, and the evaluation harness.

[Case study](https://somesh-m.vercel.app/projects/applesupport-ai) · [GitHub](https://github.com/Somesh4206/Apple-Support-Agent) — *Story · 05 / 06*
